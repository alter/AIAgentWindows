# Projects and project rooms in PLAN mode

## Goal
The app is organised by projects. A project is a code directory (existing, or new: folder plus `git init`). Its agents work in that directory; its rooms discuss the project in PLAN mode: CLI participants run in the project folder in their read-only modes with the owner's and the project's hooks kept out, web and OpenRouter participants get the history plus a project map built from `git ls-files`, and the final answer is saved by a button to `<project>/docs/plans/<room slug>.md`. Agents and rooms without a project stay under a "Без проекта" node; site logins and the OpenRouter key survive the upgrade. The third layer — roles and an orchestrator — is its own plan, `docs/plans/roles.md`, started after the owner's real run of a project room (AC5). Owner, 2026-10-24; rewritten after the agent's review on the owner's word ("перепиши", 2026-10-24).

The isolation is a CLI mechanism (first candidate `--settings '{"disableAllHooks":true}'`, then `--setting-sources`), never the owner's private `CC_DISABLED_HOOKS` variable. The room intro tells CLI participants they discuss and do not execute the project's plans. A participant's session title names the room (review 2.1, 2.2; second review 1, 3).

- D10 One room run at a time in the whole app stays (one site account in two tabs at once invites bot checks), and the ledger row states it as a limit; a site participant's page is the site agent of that kind in the room's project, never the first agent of that kind in the app; a site kind with no agent in the room's project is disabled in Add participant with the reason (review 2.5; second review 8; third review 7).

When a site adapter cannot attach the file, the participant gets the same text inlined and truncated to the composer limit, and the turn goes on (second review 5; third review 8, 9).

## Assumptions
- State moves to version 2 (src/shared/agents.ts:48) through an explicit `migrateV1` that reads the version-1 agents for their partitions before dropping them; a version-1 file yields the kept theme, sidebar width, OpenRouter key and the partition map, and no agents.
- Before the first version-2 write the app saves the version-1 file once as `agents.v1.backup.json` and never touches it again: a build from `main` reads version 2 as a mismatch, starts empty and would overwrite the file without the partition map.
- Several version-1 agents of one site kind: the kind's partition is the one whose `<userData>/Partitions/<agentId>/Cookies` was modified last (no last-used field exists in `Agent`); with no such file, the most recently created agent. The directory name Electron gives a `persist:<uuid>` partition under `Partitions/` is confirmed on the owner's real data folder by T04 before the rule is coded. The rule is a heuristic (a page opened and not signed in also writes Cookies); a wrong pick is cured by signing in once. The other old partitions stay on disk untouched (§5: deleting user data needs the owner).
- After the upgrade no agents exist, so a pre-upgrade room with a site participant under "No project" cannot continue until the owner adds that site's agent there.
- Project metadata lives in the app's data folder, never inside the project directory; the only file the app writes into a project is a saved plan.
- Room CLI sessions of a project are looked up by Claude under the project folder and therefore appear in the owner's `claude --resume` list for that project; that is accepted and the sessions carry the room title.
- A project is identified by the realpath of its folder; two projects on one folder are refused.
- If T03 finds no way to keep hooks out of a `-p` turn, D8 falls back to today's cwd (`<shared>/rooms/<kind>-<n>`) with `--add-dir <project>` for Claude and whole-disk read for Codex, and the Assumption is recorded in the task's NOTES with the T03 evidence.
