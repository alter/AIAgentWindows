# Projects and project rooms in PLAN mode

## Goal
The app is organised by projects. A project is a code directory (existing, or new: folder plus `git init`). Its agents work in that directory; its rooms discuss the project in PLAN mode: CLI participants run in the project folder in their read-only modes with no user, project or local settings file applied, the project's secrets denied to them and no web tools, web and OpenRouter participants get the history plus a project map built from `git ls-files`, and the final answer is saved by a button to `<project>/docs/plans/<room slug>.md`. Agents and rooms without a project live under a "No project" node that works as the app works today; site logins and the OpenRouter key survive the upgrade, an unreadable state file never costs them, and a build from `main` keeps working on the same data folder. The app never writes into a project folder except that saved plan. Value comes early: projects are usable after T09, project rooms with CLI participants and Save plan after T14, the project map for web and OpenRouter participants after T17. On the way the code gains the seams this plan consumes — a file store with one owner of the app state, a sidebar tree reducer, a per-run room context, a turn profile and a context pack — each right before its consumer; kind descriptors, the driver registry and scenario fixtures, whose consumers are roles, are cut in `docs/plans/roles.md`. Roles and an orchestrator are that plan, started after the owner's real run of a project room (AC5). Owner, 2026-10-24; reviewed with the owner through the day and by three rounds of independent reviewers (Log).
