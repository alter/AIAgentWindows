# Projects and project rooms in PLAN mode

## Goal
The app is organised by projects. A project is a code directory (existing, or new: folder plus `git init`). Its agents work in that directory; its rooms discuss the project in PLAN mode: CLI participants run in the project folder in their read-only modes with the owner's and the project's hooks kept out and the project's secrets denied to them, web and OpenRouter participants get the history plus a project map built from `git ls-files`, and the final answer is saved by a button to `<project>/docs/plans/<room slug>.md`. Agents and rooms without a project live under a "No project" node that works as the app works today; site logins and the OpenRouter key survive the upgrade, an unreadable state file never costs them, and a build from `main` keeps working on the same data folder. The app never writes into a project folder except that saved plan. Value comes early: projects are usable after T08, project rooms with CLI participants and Save plan after T15, the project map for web and OpenRouter participants after T19. On the way the code gains the seams the next layers need — a file store, a sidebar tree reducer, a turn profile, a per-run room context, kind descriptors and a context pack — each cut by a behaviour-neutral task right before its consumer. The third layer — roles and an orchestrator — is its own plan, `docs/plans/roles.md`, started after the owner's real run of a project room (AC5). Owner, 2026-10-24; reviewed with the owner through the day and by two rounds of three independent reviewers (Log).

## Decisions
- D1 Sidebar: one tree: project → # Rooms / Agents → items, each project collapsible, plus a "No project" node (owner; label per D14). "No project" keeps today's flows — new CLI agents with the folder picker, site and OpenRouter agents, rooms in `shared/rooms` — so what works today keeps working; inside a project an agent takes the project folder without a picker (agent's decision, reviewers 2026-10-24: the plan left it open, and a pre-upgrade room with a site participant can only continue if a site agent can be added there).
- D2 Existing test agents are not migrated (owner: "можешь удалять, мигрировать не надо"); site logins and the OpenRouter key are kept (owner: "для веба сессии ... и для openrouter ... не хочется с нуля перелогинивать"). Existing room records stay on disk and show under "No project"; the OpenRouter conversation files of dropped agents (`shared/openrouter/<agentId>.json`) stay as orphans: nothing is deleted, nothing is converted.
- D3 One site login for all projects: one persistent partition per site kind, recorded in `state.json` as `siteKind → partition`; a kind with a version-1 agent keeps its old `persist:<agentId>` (confirmed on the owner's data folder 2026-10-24, read only: `Partitions/<agentId>` without the `persist:` prefix, exactly one agent per site kind — deepseek `cfdc58b3…`, chatgpt `8182ddf2…`, grok `5dff1f45…` — plus one orphan partition of a deleted agent; the fallback for several agents of one kind is the one whose `Partitions/<id>/Cookies` was modified last, else the most recently created, with a synthetic fixture test; an agent id is used in a path only after it matches the UUID pattern, because `parseAgent` checks only "non-empty string", agents.ts:110), a kind without one gets `persist:<kind>`; a site agent still exists per project (owner). Every other partition stays on disk, logged in, never deleted by any task (§5). Several views on one partition are several `WebContentsView`s on one `session`: `configureSession` (site-views.ts:214-228) runs once per session and stays idempotent. `capture-auto-main.ts` reads agents and partitions and flushes cookies per `persist:${agent.id}` (capture-auto-main.ts:11-13, 38); both follow the partition map.
- D4 A new project creates the folder and runs `git init` (owner). `git init` into an empty new folder stays the only git write the app ever does.
- D5 Web and OpenRouter participants of a project room get the room history plus an automatic project map: the file tree from `git ls-files` (no `git` or no commits: a directory walk that honours `.gitignore` and always skips `.git/` and `node_modules/`) and README / CLAUDE.md / AGENTS.md, with a size cap, a deny list by name (`.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.keystore`, `id_*`, `*credentials*`, `*secret*`, `*.tfstate`, `*.sqlite*`, `settings.local.json`, `.npmrc`, `.netrc`, `.pypirc`, `.aws/`, `.ssh/`, `.docker/config.json`), and paths checked against the realpath of the project (owner). The same deny list, from one source, is passed to Claude room turns in a project as `permissions.deny` `Read(...)` rules (T03 names the flag and whether Grep and Glob honour them), because plan mode leaves `Read` and a bare `WebFetch` (every domain, cli-args.ts:53-54) open and a hostile `AGENTS.md` of a cloned repository could ask for `.env` and a fetch; Codex `read-only` reads the whole disk and has no fetch tool — its native web search is the accepted channel (reviewers 2026-10-24). Residual risk, accepted by the agent and recorded in the ledger row: a CLI participant's reply may quote any file it could read, and that reply is part of the history sent to web and OpenRouter participants; no redaction is built (redacting needs the secret values, i.e. reading them), the recipients line of D13 says so (reviewers 2026-10-24; the owner may reverse this).
- D6 "Save plan" writes the final entry's raw text to `<project>/docs/plans/<room slug>.md`: slug from the room title, sanitised (no `/`, `..`, control characters, ≤ 80 chars); every line among the first 8 that the owner's hooks would match (`stop-guard.sh:19-21`, `session-start.sh:13-15`: `head -n 8 | grep -qE '^status: *running *$'`, front matter or not) is rewritten to `status: draft`, because a model asked for "a plan in this repository's format" produces exactly that line, often inside a fenced block after an intro line (reviewer reproduced, 2026-10-24); an existing file overwritten only after confirmation; the target refused when a symlink (`lstat`) or when the realpath of its parent is not under the project's realpath; the temp file created exclusively; written through the file store (D18); models get no write access in rooms (owner). The owner said "PLAN.md inside the project"; `docs/plans/<slug>.md` is the agent's reading of it: one plan per room instead of one overwritten `PLAN.md`, and the path the owner's `/run docs/plans/<slug>.md` takes.
- D7 Layers in order projects → PLAN rooms → roles (owner). Roles are `docs/plans/roles.md`, started after AC5.
- D8 CLI participants of a project room run in the project folder with their read-only flags of today plus the hook isolation found by T03, so neither the owner's `~/.claude/settings.json` hooks nor the project's own `.claude/settings.json` / `settings.local.json` hooks drive a room turn (evidence: `~/.claude/hooks/stop-guard.sh:17-21` re-prompts any session whose cwd has a `docs/plans/*.md` with `status: running`; `session-start.sh:13` scans the same). - D9 Deleting a project never touches its code folder: it leaves the index, every service closes its part (D20: pty agents, site views), its storage folder goes to the Trash, after confirmation inside the sidebar; refused while its room runs (today's rule, room-service.ts:150).
