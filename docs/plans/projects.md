# Projects and project rooms in PLAN mode

## Goal
The app is organised by projects. A project is a code directory (existing, or new: folder plus `git init`). Its agents work in that directory; its rooms discuss the project in PLAN mode: CLI participants run in the project folder in their read-only modes with the owner's and the project's hooks kept out and the project's secrets denied to them, web and OpenRouter participants get the history plus a project map built from `git ls-files`, and the final answer is saved by a button to `<project>/docs/plans/<room slug>.md`. Agents and rooms without a project stay under a "No project" node; site logins and the OpenRouter key survive the upgrade, and a build from `main` keeps working on the same data folder. The app never writes into a project folder except that saved plan. On the way the code gains the seams the next layers need — a file store, a sidebar tree reducer, kind descriptors, a turn profile and a context pack — each cut by a behaviour-neutral task right before its consumer; projects are usable after T08, before any of the room seams. The third layer — roles and an orchestrator — is its own plan, `docs/plans/roles.md`, started after the owner's real run of a project room (AC5). Owner, 2026-10-24; reviewed with the owner through the day and by three independent reviewers (Log).

## Assumptions
- After the upgrade no agents exist, so a pre-upgrade room with a site participant under "No project" cannot continue until the owner adds that site's agent there.
- The app writes into a project folder only the saved plan (D6); a room turn writes nothing there (D22), proven by AC4's listing check.
- Room CLI sessions of a project are looked up by Claude under the project folder and appear in the owner's `claude --resume` list for that project under the room's name; their transcripts, project map included, land in `~/.claude/projects/<project>/`; accepted.
- A project is identified by the realpath of its folder; two projects on one folder are refused; nesting is allowed.
- If T03 finds no way to keep hooks out of a `-p` turn, D8 falls back to today's cwd (`<shared>/rooms/<kind>-<n>`) with `--add-dir <project>` for Claude (read and edit access, edits blocked by plan mode) and whole-disk read for Codex, recorded in the task's NOTES with the T03 evidence.
- Two builds on one data folder diverge after the first start of the new one: the OpenRouter key, theme and sidebar width then exist in both files, a Disconnect or a 401 in one build does not clear the other; agents added in v0.0.1 afterwards never reach the new build; "No project" room records are written by both builds (atomic rename, last writer wins; v0.0.1 drops the digest fields of D22 when it rewrites one, which `parseRoomRecord` tolerates, room-model.ts:344-359). Never run both at the same time. The working copy is on branch `projects`, so `npm start` from it is the new build.
