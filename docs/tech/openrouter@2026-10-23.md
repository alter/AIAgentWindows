# openrouter@2026-10-23

OpenRouter's API is unversioned, so this document is dated: it quotes the pages of https://openrouter.ai/docs as fetched on 2026-10-23 (the `.md` rendering of each page) and the live responses of `https://openrouter.ai/api/v1/models` and the unauthenticated error paths of the same day. Electron side: 44.6.0 docs at tag v44.6.0; Node side: the v22.20.0 docs. No API key was available, so nothing that needs a key was run; those items say "unverified".

## Sources and method

- Documentation index of all pages (`llms.txt`), used to find the canonical pages quoted below — https://openrouter.ai/docs/llms.txt
- Every OpenRouter page is quoted as `<path>.md`; the OpenAPI document behind the API reference is published as YAML and JSON — https://openrouter.ai/docs/api_reference/overview.md
- Live probes that needed no key were made with `curl` on 2026-10-23 (GET /api/v1/models, POST /api/v1/auth/keys with a junk code, GET /api/v1/key and POST /api/v1/chat/completions without credentials) and are marked "probe" — https://openrouter.ai/api/v1/models

## S1 Sign-in: OAuth PKCE (D1: loopback callback plus paste-key fallback)

- Start: send the user to `https://openrouter.ai/auth?callback_url=<YOUR_SITE_URL>&code_challenge=<CODE_CHALLENGE>&code_challenge_method=S256`; `code_challenge_method` is `S256` (recommended) or `plain`, and `code_challenge` is optional but recommended when a callback URL is given — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- S256 challenge: the page says "base64 encoding of the sha256 hash of `code_verifier`" while its sample code produces `Buffer.from(hash).toString('base64url')`; use base64url without padding as the sample does (padding handling of the server was not probed) — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Callback: after authorization the user is redirected to `callback_url` with a `code` query parameter; `state` is returned unchanged when it was sent, and is not returned when the user denies access or in headless mode — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Localhost: "Localhost callbacks are supported on **any port**", for apps that bind "an arbitrary free OS port", example `http://localhost:51423/callback`; such apps get a fixed title like `localhost:3000` and do not appear in the marketplace or rankings — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Only the host name `localhost` is documented; whether `http://127.0.0.1:<port>` is accepted is unverified. Tried: GET /auth with `callback_url` set to `http://localhost:5555/cb`, `http://127.0.0.1:5555/cb` and `ftp://bad` logged out; all three answered 307 to the sign-up page with the URL preserved, so no validation is visible without a session — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Headless / paste mode: omit `callback_url`; `https://openrouter.ai/auth?code_challenge=<CODE_CHALLENGE>&code_challenge_method=S256&key_label=<YOUR_APP_NAME>` shows the authorization code on screen for the user to paste into the app; `code_challenge` is required in this mode — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Optional auth parameters: `key_label` (prefills the key label), `workspace_id`, `required_workspace_id`, `state` — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Code lifetime: "The code is single-use and expires after 10 minutes" — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Exchange: `POST https://openrouter.ai/api/v1/auth/keys`, `Content-Type: application/json`, body `{ code: string (required), code_verifier: string, code_challenge_method: "S256" | "plain" | null }`; no Authorization header is needed — https://openrouter.ai/docs/api/api-reference/oauth/exchange-authorization-code-for-api-key.md
- Exchange response 200: `{ key: string, user_id: string | null }`, the key looks like `sk-or-v1-…` — https://openrouter.ai/docs/api/api-reference/oauth/exchange-authorization-code-for-api-key.md
- Documented exchange errors: `400 Invalid code_challenge_method`, `403 Invalid code or code_verifier`, `403 Authorization code expired`, `405 Method Not Allowed` (use POST over HTTPS) — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Probe: POST /api/v1/auth/keys with `{"code":"x","code_verifier":"y","code_challenge_method":"S256"}` answered HTTP 400 `{"error":{"message":"Invalid code","code":400}}`, not the documented 403; branch on the body message and treat 400 and 403 alike as "restart sign-in" — https://openrouter.ai/docs/api/api-reference/oauth/exchange-authorization-code-for-api-key.md
- The returned key is a normal user-controlled API key billed to the user's own credits; the user can open its settings page at `https://openrouter.ai/keys/<sha256 hex of the key>` and its activity at `https://openrouter.ai/logs?api_key_hash=<hash>` (a 404 for anyone but the owner) — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Paste-key fallback: the user creates a key by hand and pastes it; the key has the same use as an exchanged one (Bearer header); the key-creation page was not fetched, so its URL is unverified beyond the settings links above — https://openrouter.ai/docs/api_reference/overview.md

## S2 Keys: use, info, revocation

- Use: `Authorization: Bearer <key>` on every request; a request without it answers 401 `{"error":{"message":"No cookie auth credentials found","code":401}}` (probe on GET /key and POST /chat/completions) — https://openrouter.ai/docs/api_reference/overview.md
- Key info: `GET https://openrouter.ai/api/v1/key` returns `{ data: { label, limit, limit_remaining, limit_reset, include_byok_in_limit, usage, usage_daily, usage_weekly, usage_monthly, byok_usage*, is_free_tier, is_management_key, budgets[], effective_budget, free_model_daily_requests, creator_user_id, organization_id, workspace_id, allowed_data_regions, expires_at, rate_limit } }` — https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key.md
- Types: `label` string; `limit`, `limit_remaining` number (USD) or null (unlimited); `limit_reset` string or null; `usage*` numbers (USD, UTC windows); `is_free_tier` boolean, "Whether the user has paid for credits before"; `rate_limit` is deprecated, safe to ignore — https://openrouter.ai/docs/api_reference/limits.md
- `free_model_daily_requests: { used: integer, limit: integer, remaining: integer }` is the `:free` daily counter, reset at UTC midnight; `limit` is chosen by all-time credits purchased and is independent of `is_free_tier`; BYOK and exempt accounts are not gated by it — https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key.md
- Account balance is not in `GET /key`; `GET /api/v1/credits` (`{ data: { total_credits, total_usage } }`) "[Management key] required", so an exchanged key cannot read the balance — https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits.md
- Revocation: the owner deletes or disables the key on openrouter.ai; afterwards requests answer 401 with `error_type: authentication` ("The API key is missing, invalid, or revoked") and the app must drop the stored key and return to sign-in — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Management keys (`is_management_key`) cannot run inference; an exchanged key is not one — https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key.md

## S3 Models

- `GET https://openrouter.ai/api/v1/models` needs no Authorization (probe: HTTP 200 with no header); the answer is `{ data: Model[], total_count: number, links: { next: string | null } }`; probe on 2026-10-23: 468 models, `total_count` 468, `links.next` null, 790 KB, `cache-control: public, max-age=120` — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Query parameters: `offset` (default 0), `limit` (default 500, max 1000), `category`, `supported_parameters` (comma-separated filter, probe: `tools` returns 375), `output_modalities` (default `text`; `all` returned 692 models today), `sort` (`most-popular`, `newest`, `top-weekly`, `pricing-low-to-high`, `context-high-to-low`, …) — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Default list is text-output models only; image, audio, embedding, video and similar models appear only with `output_modalities` — https://openrouter.ai/docs/guides/overview/models.md
- Model object fields seen in the probe: `id`, `canonical_slug`, `hugging_face_id`, `name`, `created`, `description`, `context_length` (number), `architecture { modality, input_modalities[], output_modalities[], tokenizer, instruct_type }`, `pricing`, `top_provider { context_length, max_completion_tokens, is_moderated }`, `per_request_limits`, `supported_parameters[]`, `default_parameters`, `supported_voices`, `knowledge_cutoff`, `expiration_date`, `links { details }`, optional `reasoning`, `alias_target`, `benchmarks` — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- `pricing` values are strings, USD per token for `prompt` and `completion` (probe: all 468 `prompt` values are strings); other keys seen: `request`, `image`, `input_cache_read`, `input_cache_write`, `internal_reasoning`, `web_search`, `audio`; a model can carry two to ten of them — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- `supported_parameters` values seen in the probe (union over all models): `frequency_penalty`, `include_reasoning`, `logit_bias`, `logprobs`, `max_completion_tokens`, `max_tokens`, `min_p`, `parallel_tool_calls`, `prediction`, `presence_penalty`, `reasoning`, `reasoning_effort`, `repetition_penalty`, `response_format`, `seed`, `stop`, `structured_outputs`, `temperature`, `tool_choice`, `tools`, `top_a`, `top_k`, `top_logprobs`, `top_p`, `verbosity`, `web_search_options` — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- `expiration_date` is set on a few models (7 of 468 today, e.g. `2026-10-31`); a picker should hide or flag them — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Single model: `GET /api/v1/model/<id>` (example `poolside/laguna-s-2.1:free`) returns the catalog entry of a catalog variant, the base entry for a routing variant such as `:nitro`, 404 when the model does not exist — https://openrouter.ai/docs/guides/overview/models.md
- `:free` rule: "Append `:free` to the ID of a model that has a free entry"; it is a catalog variant, so the free version is its own entry with its own pricing, context length and endpoints, and only models that list one support it — https://openrouter.ai/docs/guides/routing/model-variants/free.md
- Probe: 17 ids end in `:free` today, all with `pricing.prompt` and `pricing.completion` equal to `"0"`; 20 text-or-router entries have zero prompt and completion price: those 17, `openrouter/free` and two `google/lyria-3-*` previews without the suffix; a free filter should test the `:free` suffix or zero prompt and completion price, and treat `openrouter/free` as the router — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Free Models Router: model id `openrouter/free` "selects a free model at random" among free models that support the features of the request (image input, tool calling, structured outputs); the chosen model is in the response `model` field — https://openrouter.ai/docs/guides/routing/routers/free-router.md
- Free variants "may have different rate limits or availability compared to paid versions"; listing a `:free` model in a `models` fallback array can fall through to a paid model that is billed at its own price — https://openrouter.ai/docs/guides/routing/model-variants/free.md
- Free-tier limits: credits purchased (all time) below 10 gives 20 requests per minute and 50 per day; at least 10 gives 20 per minute and 1000 per day; "purchase at least 10 credits to raise your daily limit" — https://openrouter.ai/docs/api_reference/limits.md
- A negative credit balance can cause errors "including for free models" — https://openrouter.ai/docs/api_reference/limits.md
- Making additional accounts or keys does not change rate limits, "we govern capacity globally"; limits differ per model — https://openrouter.ai/docs/api_reference/limits.md
- Alias ids such as `~openai/gpt-sol-latest` appear in the docs as model values and in `alias_target` of a model object; resolve through the list rather than assuming a prefix — https://openrouter.ai/docs/guides/overview/auth/oauth.md

## S4 Chat completions

- Endpoint `POST https://openrouter.ai/api/v1/chat/completions`, JSON body; "Either `messages` or `prompt` is required"; `model` falls back to the user's default when omitted, so always send it with the organization prefix — https://openrouter.ai/docs/api_reference/overview.md
- Body fields used here: `model`, `messages[] { role: 'system' | 'user' | 'assistant' | 'tool', content: string | ContentPart[], name? }`, `stream: boolean` (default false), `max_tokens` (range `[1, context_length)`), `max_completion_tokens`, `temperature` (0 to 2), `stop`, `tools`, `tool_choice`, `response_format`, `reasoning`, `plugins`, `provider` — https://openrouter.ai/docs/api_reference/overview.md
- `max_tokens` is marked deprecated in the OpenAPI schema in favour of `max_completion_tokens`; "some providers enforce a minimum of 16"; both "share semantics, including the reasoning-token caveat" — https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion.md
- `max_tokens` default when omitted is not stated for the completion itself; the credit check uses "a fixed per-request cap" in that case, and `top_provider.max_completion_tokens` of the model gives its ceiling; set it explicitly (unverified what a provider applies when it is absent) — https://openrouter.ai/docs/api_reference/limits.md
- Parameters a model does not support are ignored and the rest forwarded; sampling parameters absent from a request are omitted upstream so the provider default applies — https://openrouter.ai/docs/api_reference/parameters.md
- Non-streaming response: `{ id, choices[] { finish_reason, native_finish_reason, message { role, content: string | null, tool_calls?, reasoning?, reasoning_details?, annotations? }, error? }, created, model, object: 'chat.completion', usage }`; `usage { prompt_tokens, completion_tokens, total_tokens, prompt_tokens_details.cached_tokens, completion_tokens_details.reasoning_tokens, cost, is_byok, server_tool_use.web_search_requests }` — https://openrouter.ai/docs/api_reference/overview.md
- `finish_reason` is normalized to `tool_calls`, `stop`, `length`, `content_filter`, `error`; the raw value is `native_finish_reason` — https://openrouter.ai/docs/api_reference/overview.md
- Streaming: send `stream: true`; chunks are SSE `data: {json}` lines with `choices[].delta.content`; the stream ends with `data: [DONE]` — https://openrouter.ai/docs/api_reference/streaming.md
- SSE comments `: OPENROUTER PROCESSING` arrive to keep the connection alive; "skip lines that start with `:` before calling `JSON.parse`" — https://openrouter.ai/docs/api_reference/streaming.md
- Final usage chunk: before `[DONE]` there is an extra chunk with `usage` and one content-free choice repeating `finish_reason`, so the terminal `finish_reason` appears twice; `stream_options.include_usage` is deprecated and "has no effect", usage is always sent — https://openrouter.ai/docs/api_reference/streaming.md
- The generation id comes in the `X-Generation-Id` response header — https://openrouter.ai/docs/api_reference/streaming.md
- Cancellation: aborting the connection stops processing and billing "for supported providers" (OpenAI, Anthropic, DeepSeek and others); for unsupported providers (Google, Mistral, Groq, Bedrock and others) and for non-streaming requests the model keeps running and the full response is billed — https://openrouter.ai/docs/api_reference/streaming.md
- Attribution headers (all optional): `HTTP-Referer` (app URL, "required for app attribution"), `X-OpenRouter-Title` (`X-Title` still accepted), `X-OpenRouter-Categories` (up to 2, recognized names such as `general-chat`, `cli-agent`); "Apps using `localhost` URLs must also include `X-OpenRouter-Title` to be tracked"; `X-OpenRouter-App-Visibility: hidden` creates a new app unlisted — https://openrouter.ai/docs/app-attribution.md
- Provider routing `provider` object: `order`, `allow_fallbacks` (default true), `require_parameters` (default false), `data_collection` ("allow" default, or "deny"), `zdr`, `only`, `ignore`, `quantizations`, `sort`, `max_price`; default is price-based load balancing across top providers — https://openrouter.ai/docs/guides/routing/provider-selection.md
- Whether `data_collection: "deny"` or the account privacy settings exclude every free endpoint was not found on the pages read and is unverified — https://openrouter.ai/docs/guides/routing/provider-selection.md

## S4 Reasoning parameters

- Request object `reasoning`: `effort` one of `max`, `xhigh`, `high`, `medium`, `low`, `minimal`, `none` ("OpenAI-style") or `max_tokens` number ("Anthropic-style") "(not both)"; plus `exclude` boolean (default false) and `enabled` boolean (default inferred from `effort` or `max_tokens`) — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- OpenAPI chat schema lists `reasoning { effort, summary }` with `summary` one of `auto`, `concise`, `detailed`, and a shorthand `reasoning_effort` (same values, "Cannot be used simultaneously with reasoning.effort if they differ"); it does not list `max_tokens`, `exclude` or `enabled`, so those three come from the guide only and were not sent to a live key (unverified) — https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion.md
- Effort models: "OpenAI reasoning models (o1 series, o3 series, GPT-5 series) and Grok models"; effort allocates a share of `max_tokens`: max and xhigh about 95 %, high 80 %, medium 50 %, low 20 %, minimal 10 %, none disables — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- Token-budget models: "Gemini thinking models", Anthropic reasoning models (`reasoning.max_tokens`), some Alibaba Qwen thinking models (mapped to `thinking_budget`); for them an effort value is converted with the percentages above — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- Per-model discovery: a model object may carry `reasoning { supported_efforts, default_effort, default_enabled, supports_max_tokens, mandatory }`; `supported_efforts` is in descending order, `null` means all gateway values, absent means no effort choice; `mandatory: true` means "do not send `effort: "none"` — the model rejects it"; non-reasoning models and the routers `openrouter/auto` and `openrouter/free` omit the field — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- Probe of the list today: 336 of 468 models carry `reasoning`; 130 of them list no `supported_efforts`; the most common effort sets are `[max, xhigh, high, medium, low, none]` (33 models) and `[max, xhigh, high, medium, low]` (23); six models report `supports_max_tokens` together with efforts; free examples: `thinkingmachines/inkling:free` efforts `[max, high, medium, low, minimal, none]`, `nvidia/nemotron-3-super-120b-a12b:free` efforts `[medium, low, none]` with `supports_max_tokens`, `google/gemma-4-31b-it:free` `default_enabled: false` and no efforts, `recursive/flint-v1.0:free` `mandatory: true` — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Budget trap: reasoning tokens count against `max_tokens` "on most providers"; a small limit can be spent entirely on reasoning, giving a 200 with `finish_reason: "length"`, empty `content`, and `reasoning_tokens` close to `completion_tokens`; the reasoning is still billed; visible tokens are `completion_tokens - completion_tokens_details.reasoning_tokens` — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- Response shape: reasoning text arrives in `message.reasoning` (and `reasoning_details[]` of types `reasoning.summary`, `reasoning.encrypted`, `reasoning.text`; streaming in `delta.reasoning_details`) unless `exclude` is true; some models (OpenAI o-series) return none — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- To keep reasoning across turns send it back as `message.reasoning` or the full `message.reasoning_details` on the assistant message; needed for tool calling with Claude — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md

## S5 Web search

- Deprecation: "The web search plugin (`plugins: [{ id: "web" }]`) and the `:online` variant are deprecated. Use the `openrouter:web_search` server tool instead" — the replacement is the server tool, not the plugin — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- Server tool (beta): `tools: [{ "type": "openrouter:web_search", "parameters": { engine, mode, max_results, max_uses, max_total_results, search_context_size, max_characters, user_location, allowed_domains, excluded_domains } }]`; the model decides whether to search, 0 to N times per request — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- Engines: `auto` (default: native provider search when available, otherwise Exa), `native`, `exa`, `firecrawl`, `parallel`, `perplexity`; native search exists for OpenAI (GPT-4.1, GPT-5 and later, o3, o4-mini), Anthropic (Claude 4 and later), Google (Gemini 3 and later), SpaceXAI (Grok 4 and later) and Perplexity models — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- `max_results` default 5 (1 to 25); `max_uses` hard-caps searches per request (forwarded only to Anthropic natively); `max_total_results` caps results over all calls — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- Prices, "in addition to standard LLM token costs": Exa `instant`/`fast`/`auto` $0.007 per request, `deep-lite`/`deep` $0.012, `deep-reasoning` $0.015, up to 10 results then $0.001 per extra result; Parallel `turbo`/`fast` $0.001, `basic`/`advanced` $0.005; Perplexity $0.005; Firecrawl $0.005 per search plus $0.0125 per result; native search passed through from the provider — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- Free models: "Using web search will incur extra costs, even with free models" (plugin page, with `openai/gpt-oss-20b:free:online` as the example); the search fee is charged to credits, so an account with zero credits cannot be assumed to search — https://openrouter.ai/docs/guides/features/plugins/web-search.md
- Plugin form (deprecated, still documented): `plugins: [{ "id": "web", "engine"?, "max_results"?: 5, "search_prompt"?, "include_domains"?, "exclude_domains"? }]`; `:online` is documented there as a shortcut, with a stated equivalent of `model: openrouter/auto` plus the plugin, which does not match its own `openai/gpt-5.2:online` example — https://openrouter.ai/docs/guides/features/plugins/web-search.md
- Results appear as `message.annotations[]` of `type: "url_citation"` with `url_citation { url, title, content, start_index, end_index }` — https://openrouter.ai/docs/guides/features/plugins/web-search.md
- Search request count is reported in `usage.server_tool_use.web_search_requests` and its metered cost in `usage.cost_details` — https://openrouter.ai/docs/api_reference/overview.md
- Search plus a `:free` model together with an account below the free-tier request caps was not run (no key); whether a failed search charge blocks the request is unverified — https://openrouter.ai/docs/guides/features/server-tools/web-search.md

## Limits and errors

- Error body: `{ error: { code: number, message: string, metadata?: object } }`; the HTTP status equals `error.code` for request errors and out-of-credit errors; otherwise "the returned HTTP response status will be `200`" and the error is in the body or in an SSE event — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Codes: 400 bad request, 401 invalid credentials, 402 insufficient credits, 403 forbidden (permissions, guardrail, moderation), 408 timeout, 429 rate limited, 502 model down or invalid response, 503 no provider meets the routing requirements — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- `Retry-After` (seconds) may come on 429, on 503 and on 402 whose `error.metadata.limit_source` is `openrouter_in_flight_budget`; a 402 without it is not a wait-and-retry case; the common SDKs do not retry 402 on their own — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- 402 `metadata.limit_source`: `openrouter_in_flight_budget` (transient, wait for `Retry-After`), `openrouter_credits` (balance cannot cover it, or `reason: weight_exceeds_budget`: lower `max_tokens` or the prompt, or add credits), `openrouter_key_limit` (key credit cap spent); branch on `limit_source`, not on `remedy_hint` text — https://openrouter.ai/docs/api_reference/limits.md
- 403 budget errors carry `metadata { limit_source: openrouter_guardrail_budget | openrouter_workspace_budget | openrouter_key_limit, scope, limit_usd, spend_usd, resets_at }` and no `Retry-After` — https://openrouter.ai/docs/api_reference/limits.md
- 429: body `{ error: { code: 429, message: "Rate limit exceeded", metadata: { error_type: "rate_limit_exceeded" } } }`; it comes from OpenRouter (free-model per-minute or per-day caps, DDoS protection) or from the upstream provider (`metadata.provider_code`); platform 429s carry `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; successful responses carry no `X-RateLimit-*` headers — https://openrouter.ai/docs/api_reference/limits.md
- Typed codes in `error.metadata.error_type`: `context_length_exceeded`, `authentication` (401), `permission_denied` (403), `payment_required` (402), `rate_limit_exceeded` (429), `provider_overloaded` (503), `provider_unavailable` (502), `invalid_request` (400), `not_found` (404), `payload_too_large` (413), `timeout` (504), `server` (500) — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Pre-stream errors are plain JSON with the real HTTP status (invalid key, malformed request, 402, 429, all providers exhausted); a non-2xx answer to a `stream: true` request is not SSE — https://openrouter.ai/docs/api_reference/streaming.md
- Mid-stream errors: "OpenRouter sends you the HTTP `200 OK` status and headers as soon as the provider accepts the request"; later failures arrive as an SSE `data:` chunk with a top-level `error` object and `choices[0].finish_reason: "error"`, after which the stream ends; the error can be the first and only event, so "treat a `200` carrying an `error` chunk with no content as a failure" — https://openrouter.ai/docs/api_reference/streaming.md
- `error.code` is a number in the typed-error pages but the streaming page's example shows a string (`"server_error"`); parse it tolerantly and prefer `error.metadata.error_type` — https://openrouter.ai/docs/api_reference/streaming.md
- Non-streaming: a provider failure after the headers gives `200` with a body that holds only `error` and no `choices` ("Check the body for an `error` field even on a `200`"), or `choices[0].finish_reason: "error"` with `choices[0].error` next to partial content — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Empty output: a `200` with empty `content` can be a cold start, scale-up, or a reasoning model that spent the whole `max_tokens` on reasoning; the last case is not cured by retrying — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Credit limits: the in-flight spending budget estimates each paid request from `max_tokens` (or a fixed cap when unset) and rejects with 402 before reaching a provider; it does not apply to free models — https://openrouter.ai/docs/api_reference/limits.md

## S6 Electron 44.6.0 and Node 22 side

- `safeStorage.isEncryptionAvailable()` returns boolean; "On MacOS, returns true if Keychain is available"; on Windows true once `ready` fired; on Linux true once `ready` fired and the secret key is available — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md#L58-L65
- `safeStorage.encryptString(plainText: string)` returns a `Buffer` and throws if encryption fails; `safeStorage.decryptString(encrypted: Buffer)` returns the string; store the Buffer (for example base64) in the app state file, never the plain key — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md#L75-L88
- macOS: keys live in Keychain and are protected from other users and other apps in the same userspace; calls "can block the current thread to collect user input"; the app "should be code signed" or Keychain may re-prompt on every update — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md#L14-L36
- Async API (`isAsyncEncryptionAvailable()`, `encryptStringAsync`, `decryptStringAsync` returning `{ shouldReEncrypt, result }`) is recommended over the sync one, which "may be deprecated in a future version"; if `shouldReEncrypt` is true call decrypt again and store the result — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md#L8-L12
- Linux without a secret store: items are encrypted with a hardcoded plaintext password; `getSelectedStorageBackend()` returns `basic_text` then, and the app should warn or refuse to store the key — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md#L25-L27
- `shell.openExternal(url[, options])` returns `Promise<void>`; `url` is "Max 2081 characters on Windows"; it opens the URL in the desktop's default manner — https://github.com/electron/electron/blob/v44.6.0/docs/api/shell.md#L46-L68
- Security checklist item 15: "Do not use `shell.openExternal` with untrusted content"; open only the fixed `https://openrouter.ai/auth?...` URL built by the main process, never a URL from a renderer message or a page — https://github.com/electron/electron/blob/v44.6.0/docs/tutorial/security.md#L686-L705
- `server.listen(port, host)`: "If `port` is omitted or is 0, the operating system will assign an arbitrary unused port, which can be retrieved by using `server.address().port` after the `'listening'` event"; `server.address()` is `null` before `'listening'` and after `close()` — https://github.com/nodejs/node/blob/v22.20.0/doc/api/net.md#L633-L637
- "If `host` is omitted, the server will accept connections on the unspecified IPv6 address (`::`)" (and usually IPv4 as well), so pass `'127.0.0.1'` explicitly to keep the callback server off other interfaces — https://github.com/nodejs/node/blob/v22.20.0/doc/api/net.md#L637-L643
- `http.createServer` is a `net.Server`, so `listen(0, '127.0.0.1', cb)` is the whole recipe for a random-port loopback callback listener; the Electron 44.6.0 main process runs Node 24.21.0 (see `docs/tech/electron@44.6.0.md`), the machine's tools run Node 22 — https://github.com/nodejs/node/blob/v22.20.0/doc/api/http.md#L1426-L1432 and https://github.com/nodejs/node/blob/v22.20.0/doc/api/http.md#L1815-L1818
- Not verified: whether a browser resolves `localhost` to `::1` first and then falls back to a listener bound only to `127.0.0.1`; OpenRouter documents only `localhost` in `callback_url`, so the redirect URL should say `localhost` and the listener must be reachable by it — https://openrouter.ai/docs/guides/overview/auth/oauth.md

## Implications for this app

- Shortest sign-in: a "Connect OpenRouter" button in the main process starts `http.createServer` on `127.0.0.1` port 0, builds `callback_url = http://localhost:<port>/callback` with an S256 `code_challenge` and a random `state`, opens `https://openrouter.ai/auth?...&key_label=<app name>` with `shell.openExternal`, answers the one callback request with a "you can close this tab" page, checks `state`, then does one `POST /api/v1/auth/keys` with `{ code, code_verifier, code_challenge_method: "S256" }` and stores `key`; close the server after the first callback or after 10 minutes (code lifetime) — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Fallback when the callback cannot be reached (no browser, listener refused, `localhost` mismatch): a field to paste either a key created by hand or the code shown by the headless URL (no `callback_url`, `code_challenge` required), exchanged the same way; treat exchange errors 400 and 403 as "start sign-in again" — https://openrouter.ai/docs/guides/overview/auth/oauth.md
- Key storage: encrypt with `safeStorage` in the main process (async API preferred, `isAsyncEncryptionAvailable()` first), keep only the ciphertext in the app state file, never send the key to the renderer or to site views, refuse or warn on Linux `basic_text`, and note that an unsigned macOS build may re-prompt for Keychain access; on 401 delete it and return to sign-in — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md
- Model list: call `GET /api/v1/models` (no key, answer cached 120 s, 790 KB, 468 models today) once per session and cache it; keep text-output models only (the default), show `context_length`, `pricing.prompt` and `pricing.completion` converted from per-token USD strings, and a Free filter that matches ids ending in `:free` or zero prompt and completion price, with `openrouter/free` as its own "any free model" entry; hide entries whose `expiration_date` is past — https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties.md
- Free-tier awareness: read `GET /api/v1/key` after sign-in and show `free_model_daily_requests.remaining` of `limit` (50 under 10 lifetime credits, 1000 otherwise) and the 20 per minute cap; a Room round with several free participants spends several of those requests — https://openrouter.ai/docs/api_reference/limits.md
- Room turns: one non-streaming `POST /chat/completions` per participant turn (`stream: false`), parse `choices[0].message.content`, read `usage` and `choices[0].finish_reason`, and check `error` in the body even on HTTP 200; this matches the Room's one-process-per-turn shape and avoids partial-text handling — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Chat pane: `stream: true`, parse SSE by hand or with a parser, skip lines starting with `:`, stop at `data: [DONE]`, accumulate `choices[0].delta.content`, treat the last chunk's `usage` as accounting, abort the request on Stop (billing stops only for supported providers) — https://openrouter.ai/docs/api_reference/streaming.md
- Reasoning effort mapping: offer an effort control only when the model's `reasoning.supported_efforts` is non-empty (values in the list, `none` only when listed and `mandatory` is false), a token-budget control when `supports_max_tokens` is true, nothing when neither; send `reasoning: { effort }` or `reasoning: { max_tokens }`, never both; when reasoning is on set `max_tokens` well above the expected reasoning length and treat `finish_reason: "length"` with empty content as "raise the limit", not as a retry case — https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md
- Web search: expose it as an opt-in toggle per participant that adds `tools: [{ "type": "openrouter:web_search", "parameters": { "max_results": 3, "max_uses": 2 } }]` (the plugin and `:online` are deprecated), warn that each search is billed in credits (Exa $0.007 per request) even on a `:free` model, and read `usage.server_tool_use.web_search_requests` for the count — https://openrouter.ai/docs/guides/features/server-tools/web-search.md
- Errors: 401 clear the key and show sign-in; 402 show "out of credits" with the `limit_source` (wait and retry once only for `openrouter_in_flight_budget` using `Retry-After`); 429 retry with backoff honouring `Retry-After`, and tell the user the free daily cap when `free_model_daily_requests.remaining` is 0; 502 and 503 retry once, then offer another model; a `200` with `error` or `finish_reason: "error"` is a failed turn, shown as such in the Room feed and never as an empty answer — https://openrouter.ai/docs/api_reference/errors-and-debugging.md
- Attribution: send `HTTP-Referer` and `X-OpenRouter-Title` with the app name on every request; with a localhost-only referer the title is required, and `X-OpenRouter-App-Visibility: hidden` keeps a new app out of public rankings — https://openrouter.ai/docs/app-attribution.md
- Privacy and routing defaults to decide in the build task: `provider.data_collection` defaults to "allow" and fallbacks are on; a `models` fallback array that starts with a `:free` model can end on a paid one that is billed — https://openrouter.ai/docs/guides/routing/provider-selection.md
