- `--sandbox` (`-s`) takes `read-only`, `workspace-write`, `danger-full-access`; `read-only` is the enum default of `SandboxMode` (`{R}/codex-help-flags.txt`) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/protocol/src/config_types.rs#L104-L114
- `read-only` projects to a file-system policy that grants `Read` on the root and nothing else; the sandbox reads the whole disk, writes are confined — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/protocol/src/permissions.rs#L2055-L2068
- `--ask-for-approval` (`-a`) takes only `on-request` (default) and `never` on the 0.163.0 command line; `never` is "Never ask for user approval. Failures are immediately returned to the model" (`{R}/codex-help-flags.txt`). With `on-request` a command the sandbox refuses can raise an approval prompt in the TUI, and the turn then waits for a person; the Room session therefore needs `-a never` or its turn ends only by timeout — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/protocol/src/protocol.rs#L1092-L1115
- The owner's own turns record `approval_policy`/`sandbox_policy.type` in each `turn_context` record: `on-request`/`workspace-write` (63 turns) and `never`/`danger-full-access` (27 turns) (`{R}/codex-turn-signal.txt`). A room session can read that record to assert it really runs `read-only` before it trusts the session — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rollout/src/policy.rs#L130-L145
- End of a turn: the rollout holds an `event_msg` record with `payload.type == "task_complete"` (wire name of `TurnCompleteEvent`, alias `turn_complete`), with `turn_id`, `last_agent_message` (string or null), optional `error` (`{message, codex_error_info}`), `started_at`, `completed_at`, `duration_ms`. In 82 owner turns: 68 ended with a string reply, 13 with `error` set and no reply, 1 with neither (`{R}/codex-turn-signal.txt`). The room driver treats `error` as a failed turn and a null `last_agent_message` as "no reply" — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/protocol/src/protocol.rs#L2266-L2285
- `TurnComplete` and `TurnAborted` are both persisted; a turn that the user interrupts ends with `turn_aborted`, not `task_complete`, so the driver must watch both — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rollout/src/policy.rs#L130-L145
- Paginated rollouts (`session_meta.payload.history_mode == "paginated"`) are still one `rollout-<timestamp>-<uuid>.jsonl` file under `sessions/YYYY/MM/DD/`; every record carries an `ordinal`. In the owner's 13 rollouts the 0.154.0 to 0.163.0 ones are paginated, the 0.129.0-alpha.15 ones are legacy (no `history_mode`); `task_complete` appears in both (`{R}/codex-turn-signal.txt`) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rollout/src/ordinal.rs and https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rollout/src/recorder.rs#L1744-L1750
- In a paginated rollout the reply is in three places: `task_complete.last_agent_message`; `event_msg/item_completed` with `item.type == "AgentMessage"`, `item.phase == "final_answer"` and `item.content` blocks of type `Text`; and `response_item` with `role == "assistant"`, `phase == "final_answer"` and `output_text` blocks. Intermediate chatter has `phase == "commentary"` (165 commentary vs 69 final in the owner's rollouts), so "last assistant `response_item`" (the 0.159.2 doc) can return a commentary line; the driver reads `task_complete.last_agent_message`, and falls back to the last `final_answer` item (`{R}/codex-turn-signal.txt`)
- `codex migrate-rollouts` without `--apply` only reports: on this machine "13 scanned, 1 eligible, 12 already paginated" (a dry run, nothing migrated) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rollout/src/lib.rs
- `codex resume [SESSION_ID] [PROMPT]`: a UUID or a session name; `--last`; no option of `codex` sets the id of a new session (`{R}/codex-help-flags.txt`)
- 0.163.0 runs the TUI against a "shared local app-server daemon" (`codex agents` lists its sessions, `--no-daemon` runs without it); its rollouts still land in the same `sessions/` tree (the two 0.163.0 rollouts of 2026-10-21). With a daemon whose feature settings differ from the CLI's, the TUI opens a blocking dialog ("Background server has incompatible feature settings ... 1. Run without daemon this time 2. Restart with these settings 3. Cancel", `tasks/10-app-shell/01-app-skeleton/codex-daemon-mismatch.txt`); a room session cannot answer it, so T04 starts room codex sessions with `--no-daemon`, which also puts the thread in the CLI's own process where the command-line `--sandbox` applies. The `turn_context` assertion above is the runtime check (`{R}/codex-help-flags.txt`)
- `--add-dir` still adds writable roots, never read roots; read access to `<shared>` needs nothing in read-only (the sandbox reads the whole disk, CX8) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/utils/cli/src/shared_options.rs
- Start-up update check: config key `check_for_update_on_startup` (boolean, default `true`: "checks for Codex updates on startup and surfaces update prompts"), read by the TUI at `codex-rs/tui/src/updates.rs` lines 28 and 153 (`!config.check_for_update_on_startup` returns before any prompt); a `-c key=value` override sets it for one run. ## T20: non-interactive room turns (`codex exec`)

Source read at tag `rust-v0.163.0` (`codex-rs/exec/src/{lib,cli,exec_events,event_processor_with_jsonl_output}.rs`) and `codex exec --help`, `codex exec resume --help` of 0.163.0; no prompt was sent. The probe output is `tasks/10-app-shell/02-room/spikes/print-mode-flags.txt`.

- Command shape: `codex exec [OPTIONS] [PROMPT]` and `codex exec [OPTIONS] resume [SESSION_ID] [PROMPT]`; a prompt of `-` is read from stdin, and a positional prompt plus a piped stdin appends the stdin as a `<stdin>` block, so the room passes `-` and writes the prompt to stdin (no argv leak, no stray block) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L2370-L2397
- Flags the plan assumed that `exec` does not accept: `-a/--ask-for-approval` ("unexpected argument '-a'") and `--no-daemon` ("unexpected argument '--no-daemon'"); `exec` forces `approval_policy: Never` itself and runs the app server in-process, so neither is needed — `tasks/10-app-shell/02-room/spikes/print-mode-flags.txt`, https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L591 and #L1022
- `--sandbox/-s` is an option of `exec`, not of `exec resume`: `codex exec resume --sandbox read-only` fails ("unexpected argument '--sandbox'"), `codex exec --sandbox read-only resume <id> -` parses; the CLI value becomes `sandbox_mode` of the config and of the `thread/resume` request, so it applies to a resumed thread — `tasks/10-app-shell/02-room/spikes/print-mode-flags.txt`, https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L1468-L1490
- `--json` and `--skip-git-repo-check` are global (valid before and after `resume`); outside a git repository `exec` exits 1 with "Not inside a trusted directory and --skip-git-repo-check was not specified", and a room participant folder is not a repository, so the flag is required — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/cli.rs#L37-L38 and https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L1014-L1019
- `exec` has no start-up update check or dialog: `check_for_update_on_startup` appears in the TUI only (`codex-rs/tui/src/updates.rs`), zero hits in `codex-rs/exec/src`; the room no longer passes it — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs
- Resume by id: a UUID is returned as the thread id with no cwd filter (`Uuid::parse_str(session_id).is_ok()` returns it); `--last` and thread names filter by cwd. The first turn has no id: it is created by `codex exec` and reported in the first event — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L1923-L1925
- `--json` prints one JSON object per line, `ThreadEvent` tagged by `type`: `thread.started` (`thread_id`, "Can be used to resume the thread later"), `turn.started`, `item.started`/`item.updated`/`item.completed` (`item` = `{id, type, ...}`; `type: "agent_message"` has `text`; other types `reasoning`, `command_execution`, `file_change`, `mcp_tool_call`, `collab_tool_call`, `web_search`, `todo_list`, `error`), `turn.completed` (`usage`), `turn.failed` (`error: {message}`), `error` (`message`) — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/exec_events.rs#L9-L38
- End of turn: `turn.completed` (the last `agent_message` item is the final reply; commentary messages are `agent_message` items too, so the reply is the last one) or `turn.failed` (`error.message`, with `additional_details` appended in parentheses); a bare `error` event is not terminal (`will_retry` errors are emitted too); an interrupted turn emits neither, the process ends with exit code 1; after a failed turn or a non-retried error the exit code is 1 — https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/event_processor_with_jsonl_output.rs#L447-L562 and https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec/src/lib.rs#L1340-L1360
