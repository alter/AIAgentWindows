# electron@44.6.0

Pinned 2026-10-21: newest release at least two weeks old (44.6.0 published 2026-10-06; 45.0.0 published 2026-10-21 was too new). Chromium 152.0.7977.130, Node 24.21.0 (spike log `tasks/05-feasibility/01-evidence-table/spikes/claude-run.out`).

## Types and limits used by the design

- Clipboard is asynchronous and W3C-shaped: `clear`, `has(mimetype)`, `read()`, `readText()`, `write(ClipboardItem[])`, `writeText()`; `readImage`, `writeImage`, `availableFormats` do not exist (runtime probe and typings in `tasks/05-feasibility/01-evidence-table/spikes/electron-clipboard-api.txt`) — https://github.com/electron/electron/blob/v44.6.0/docs/api/clipboard.md
- `File.path` was removed in 32.0; a dropped file's path comes from `webUtils.getPathForFile(file)` in a preload — https://github.com/electron/electron/blob/v44.6.0/docs/breaking-changes.md#L981-L983
- `safeStorage.getSelectedStorageBackend()` (Linux) returns `basic_text` when no secret store is available; items are then unprotected — https://github.com/electron/electron/blob/v44.6.0/docs/api/safe-storage.md
- `session.setPermissionRequestHandler` receives `media` (microphone, camera) with the requesting URL; `setPermissionCheckHandler` receives the requesting origin — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md
- `webContents.executeJavaScriptInIsolatedWorld(worldId, scripts)` runs code in an isolated context of the page — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md
- The `<webview>` tag is discouraged ("We currently recommend to not use the webview tag"); alternatives are `WebContentsView` or an iframe — https://github.com/electron/electron/blob/v44.6.0/docs/api/webview-tag.md
- `webContents.debugger` attaches CDP from the main process; CDP `DOM.setFileInputFiles` sets files on a file input — https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md and https://chromedevtools.github.io/devtools-protocol/tot/DOM/#method-setFileInputFiles
- A partition named `persist:<name>` is stored on disk, any other name is in memory; `sessionData` must be overridden before `ready` — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md and https://github.com/electron/electron/blob/v44.6.0/docs/api/app.md
- `NSMicrophoneUsageDescription` must be set in Info.plist for microphone access on macOS — https://github.com/electron/electron/blob/v44.6.0/docs/api/system-preferences.md#L360

## Known issues and pitfalls

- (Superseded by T33: every site view now sends the owner user agent, see below.) The default user agent carries `Electron/44.6.0`; chat.deepseek.com answers it with an "Abnormal usage environment" dialog, and shows its normal sign-in form when the token is removed (spike screenshots `web-deepseek.png`, `web-deepseek-plain-ua.png` in `tasks/05-feasibility/01-evidence-table/spikes/`) — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#contentssetuseragentuseragent
- Google forbids its OAuth sign-in inside an embedded user agent that can inject scripts or read cookies, which an Electron view is: "Sign in with Google" on the three sites is expected to fail — https://developers.google.com/identity/protocols/oauth2/policies
- Ubuntu 24.04+ restricts unprivileged user namespaces through AppArmor, which breaks the Chromium sandbox of unpacked/AppImage builds; electron-builder installs an AppArmor profile (`appArmorProfile`) and a SUID `chrome-sandbox` from its `.deb` after-install script — https://documentation.ubuntu.com/release-notes/24.04/ and https://github.com/electron-userland/electron-builder/blob/electron-builder@26.17.0/packages/app-builder-lib/templates/linux/after-install.tpl

## User agent and client hints (studied for T33, 2026-10-22)

- `session.setUserAgent(ua)` sets the UA string for requests and pages of WebContents created after the call; it does not touch `navigator.userAgentData`, which keeps the engine's brands (`Chromium` 152, no `Google Chrome`) — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md and EVIDENCE W15, W22.
- The one mechanism that covers page JS (`navigator.userAgent`, `navigator.userAgentData.brands`, `getHighEntropyValues`), iframes and dedicated workers is CDP `Emulation.setUserAgentOverride` with `userAgentMetadata` (brands, fullVersionList, platform, platformVersion, architecture, model, mobile, bitness, wow64) sent through `webContents.debugger` — https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setUserAgentOverride and https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md. It persists across navigations of that WebContents; a popup is a new WebContents and needs the command again (`did-create-window`); sent before the first navigation it waits for the renderer and returns after it, so the app does not await it. The app shares the debugger with the adapter runner (`DOM.setFileInputFiles`): both attach only when not attached.
- Header rewriting in `session.webRequest.onBeforeSendHeaders` was not chosen: it does not change the JS side, and Electron 44.6.0 sends no `Sec-CH-UA*` request header at all on localhost (EVIDENCE W23), so there is nothing to rewrite and adding headers Electron never sends would be a new signal. Revisit if a site objects. — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-request.md#L98 (`onBeforeSendHeaders`) and the no-header probe of EVIDENCE W23
- The string lives in `OWNER_USER_AGENT` (`src/shared/site-policy.ts`); the brand major comes from it, the full version of both brands from `process.versions.chrome` (the real engine), the platform version from `process.getSystemVersion()`. — https://github.com/electron/electron/blob/v44.6.0/docs/api/process.md#L121 (`process.versions.chrome`) and https://github.com/electron/electron/blob/v44.6.0/docs/api/process.md#L236 (`process.getSystemVersion()`)

## Hidden and covered site views (studied for T34, 2026-10-22)

- A `WebContentsView` with `setVisible(false)` gets no `requestAnimationFrame`, `ResizeObserver` or `IntersectionObserver` callbacks; timers still run and `document.visibilityState` stays `visible` (EVIDENCE W25, source `tasks/10-app-shell/02-room/spikes/raf-probe.txt`). The Room hid every site view that way, so a chat page that renders streamed text in a frame callback (DeepSeek turns of 2026-10-22 07:56-09:02 are consistent with it) did not change its DOM. — https://github.com/electron/electron/blob/v44.6.0/docs/api/view.md#L127 (`view.setVisible`) and https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents-view.md
- Without `disable-backgrounding-occluded-windows` and `disable-renderer-backgrounding` (`app.commandLine.appendSwitch`, before `ready`) no view renders while the app window is covered, minimized or on another Space (W26) — https://github.com/electron/electron/blob/v44.6.0/docs/api/command-line-switches.md, https://github.com/electron/electron/blob/v44.6.0/docs/api/app.md#appcommandline-readonly
- A view that is not shown lives in a second `BrowserWindow` that is never shown (`show: false`, `focusable: false`, `skipTaskbar: true`) with `view.setVisible(true)`; `BaseWindow.contentView.removeChildView` then `addChildView` moves it without a reload, its viewport keeps the bounds set after the move, and ResizeObserver/IntersectionObserver fire (W26) — https://github.com/electron/electron/blob/v44.6.0/docs/api/view.md and https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents-view.md
- The CDP debugger of the T33 user-agent override and the isolated world belong to the `webContents`, not to the window: both survive the move and the trusted `sendInputEvent` Enter works on a parked view (W28). — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L2546 (`contents.debugger` is a property of the WebContents) and https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md#L66-L74 (`attach`, `isAttached`)
- `BrowserWindow.getAllWindows()` lists the newest window first; once the parking window exists, index 0 is the parking window, not the main window — find the main window by its `file:` URL. — https://github.com/electron/electron/blob/v44.6.0/docs/api/browser-window.md#L468 (`BrowserWindow.getAllWindows()`; the docs promise no order, the newest-first order is the observed behaviour of EVIDENCE W26)
- Playwright's Electron loader already appends both switches to every launched app, so the smoke cannot show them missing (W27). — https://github.com/microsoft/playwright/blob/v1.63.0/packages/playwright-core/src/server/electron/loader.ts#L25-L28 (the loader appends every `chromiumSwitches()` entry with `app.commandLine.appendSwitch`) and https://github.com/microsoft/playwright/blob/v1.63.0/packages/playwright-core/src/server/chromium/chromiumSwitches.ts#L56 and https://github.com/microsoft/playwright/blob/v1.63.0/packages/playwright-core/src/server/chromium/chromiumSwitches.ts#L74

## Site debug recording through the shared debugger (T37, 2026-10-22)

- `webContents.debugger` emits `message` with `(event, method, params, sessionId)` for every CDP event of an enabled domain and `removeListener` takes the same listener back — https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md
- CDP `Network.enable` / `Network.disable` switch the Network domain on and off for the session; `Network.requestWillBeSent`, `responseReceived` (`response.mimeType`, `response.status`), `loadingFinished` (`encodedDataLength`, `timestamp` in monotonic seconds) and `loadingFailed` (`errorText`) carry the lifecycle; `Network.getResponseBody` returns `{ body, base64Encoded }` and fails for a resource whose body Chromium did not keep (a streamed response may be one) — https://chromedevtools.github.io/devtools-protocol/tot/Network/
- The recorder enables the Network domain only for the length of one turn, on the debugger the user-agent override already attached, and never detaches it: `Emulation.setUserAgentOverride` belongs to the Emulation domain and survives `Network.disable`. — https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md#L49 (the `message` event) and https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setUserAgentOverride (the override that survives `Network.disable`)

## OOPIF user agent (07-site-challenge T03, 2026-10-23)

- `Emulation.setUserAgentOverride` sent on the view's own debugger target covers that target's renderer only; a cross-site iframe that Chromium runs in its own process (out-of-process iframe, e.g. the Turnstile frame on challenges.cloudflare.com) is a separate DevTools target and keeps the engine's user agent and brands (spike of 07-site-challenge, `NOTES.md`). — https://chromedevtools.github.io/devtools-protocol/tot/Target/ (targets of type `iframe`)
- `Target.setAutoAttach {autoAttach, waitForDebuggerOnStart, flatten}` attaches to related targets (iframes, workers), including those that already exist; with `flatten: true` the commands and events of a child session are addressed by `sessionId` on the same connection; "you might want to call this recursively for auto-attached targets to attach to all available targets" (so it is repeated inside every child session). — https://chromedevtools.github.io/devtools-protocol/tot/Target/#method-setAutoAttach
- `Target.attachedToTarget` carries `sessionId`, `targetInfo` (`type`, `url`) and `waitingForDebugger`; `Target.detachedFromTarget` carries the `sessionId` and may come more than once. A target paused by `waitForDebuggerOnStart` runs only after `Runtime.runIfWaitingForDebugger` on its session. — https://chromedevtools.github.io/devtools-protocol/tot/Target/#event-attachedToTarget, https://chromedevtools.github.io/devtools-protocol/tot/Target/#event-detachedFromTarget and https://chromedevtools.github.io/devtools-protocol/tot/Runtime/#method-runIfWaitingForDebugger
- Electron: `debugger.sendCommand(method[, commandParams, sessionId])` sends to the child session; the `message` event is `(event, method, params, sessionId)` where `sessionId` is the session the event came from; `sendCommand` called before the target has navigated may not resolve until the navigation, so the app does not chain the auto-attach command behind the override. — https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md#L49 (`message`) and https://github.com/electron/electron/blob/v44.6.0/docs/api/debugger.md#L80 (`sendCommand`)
Project observation (not documentation): Observed in `electron-smoke` (Electron 44.6.0, n=1 per variant): with `waitForDebuggerOnStart: true` a child session that received its override, nested auto-attach and `Runtime.runIfWaitingForDebugger` pipelined without waiting for the replies left the iframe at an empty document (the session detached with no `Target.targetInfoChanged`); the same commands awaited one after another with the resume last let it load. The app awaits them in that order.
Project observation (not documentation): Dedicated workers get the page's override with the page (the claim of "User agent and client hints" above); the app resumes every attached target and sends its own override to `page` and `iframe` targets only. Refusals are logged as `user-agent-override-failed`.
Project observation (not documentation): The test cannot start a browser outside `electron-smoke`; `tests/full/site-ua-frames.spec.ts` serves a `localhost` page with a `127.0.0.1` iframe and compares `processId`, `navigator.userAgent`, `userAgentData` and the fetch `User-Agent` of both frames.

## Main-process and IPC APIs used by the app shell (studied for T01, 2026-10-21)

- `WebContentsView` extends `View`, is main-process only and unusable before `app` emits `ready`; `new WebContentsView({ webPreferences, webContents })` — `webContents` adopts an existing one, which may sit in only one view at a time; the page is `view.webContents`; built-in classes cannot be subclassed — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents-view.md#L40-L56
- A view is attached with `win.contentView.addChildView(view)` (the window is a `BaseWindow` or `BrowserWindow`); `contentView` is the root `View` of the window — https://github.com/electron/electron/blob/v44.6.0/docs/api/base-window.md#L429

- The window's client area is `win.getContentBounds()`; the `resize` event fires after a resize (use it to re-lay the views) — https://github.com/electron/electron/blob/v44.6.0/docs/api/base-window.md#L239-L241 and https://github.com/electron/electron/blob/v44.6.0/docs/api/base-window.md#L807-L809
- Navigation state: `contents.navigationHistory.canGoBack()`, `canGoForward()`, `goBack()`, `goForward()`; the `contents.canGoBack()` family is deprecated — https://github.com/electron/electron/blob/v44.6.0/docs/api/navigation-history.md#L21-L57 and https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L1223-L1235
- `contents.reload()`, `contents.loadURL(url)`, `contents.setUserAgent(ua)` (overrides for that page) and `contents.close()` (destroys the WebContents, emits `destroyed`; a destroyed WebContents is unusable) — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L1174-L1187 and https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L1375-L1379
- `contents.setWindowOpenHandler(handler)` receives `{ url, frameName, features, disposition, referrer, postBody }` and returns `{ action: 'deny' }` or `{ action: 'allow' }`; any other return value (null, undefined, unknown action) is treated as `deny` and logged — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L1464-L1495
- `will-navigate` and `did-navigate` fire only for the main frame; `will-frame-navigate` also covers subframes — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-contents.md#L246-L302
- `session.fromPartition('persist:name')` returns the on-disk session; `setPermissionRequestHandler(handler)` and `setPermissionCheckHandler(handler)` are set per session — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md#L26 and https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md#L958
- `shell.trashItem(path)` (main process) moves a path to the OS trash (Trash on macOS) and returns `Promise<void>` that resolves when done and rejects on an error while removing the item; the path must use the platform separator, so pass it through `path.resolve()`. The page does not say what happens for a path that does not exist, so the Room delete checks existence itself and treats a rejection as a failed delete of that path, never as a reason to unlink it — https://github.com/electron/electron/blob/v44.6.0/docs/api/shell.md#L71-L91
- `dialog.showOpenDialog([window, ]options)` returns `Promise<{ canceled, filePaths, bookmarks? }>`; `properties: ['openDirectory']` selects folders, `createDirectory` is macOS only; a cancelled dialog gives `filePaths: []`; the sync variant `showOpenDialogSync` blocks the main process — https://github.com/electron/electron/blob/v44.6.0/docs/api/dialog.md#L99-L145
- `dialog` is a main-process call; Playwright does not intercept it, tests replace `dialog.showOpenDialog` through `electronApp.evaluate` — https://github.com/microsoft/playwright/blob/v1.63.0/docs/src/electron-api/class-electron.md#L52-L80
- `ipcMain.handle(channel, listener)` answers `ipcRenderer.invoke(channel, ...args)`; the listener gets `(event: IpcMainInvokeEvent, ...args)` and may return a Promise whose value is sent back; `removeHandler(channel)` removes it — https://github.com/electron/electron/blob/v44.6.0/docs/api/ipc-main.md#L97-L160
- Every IPC message can come from any frame of any web contents of the app, so a handler validates `event.senderFrame` (check `frame.origin`; the frame may be `null`) before acting — https://github.com/electron/electron/blob/v44.6.0/docs/tutorial/security.md#L743-L775
- `contextBridge.exposeInMainWorld(apiKey, api)` puts `window[apiKey]`; `Function` values are proxied, everything else is copied and frozen; supported types are Function, string, number, Array, boolean and nested objects of these (and Promise, Error, plain objects per the table); Symbol is dropped, classes and prototypes do not cross; `ipcRenderer` itself cannot be sent over the bridge (expose narrow wrapper functions instead) — https://github.com/electron/electron/blob/v44.6.0/docs/api/context-bridge.md#L50-L56 and https://github.com/electron/electron/blob/v44.6.0/docs/api/context-bridge.md#L79-L153
- Context isolation exposes a preload's objects only through `contextBridge`; enabling it does not make exposing raw `ipcRenderer.send` safe — https://github.com/electron/electron/blob/v44.6.0/docs/tutorial/context-isolation.md#L55
- Since Electron 20 renderers are sandboxed by default; `nodeIntegration: true` disables the sandbox for that renderer, so the app's renderer keeps `nodeIntegration: false` — https://github.com/electron/electron/blob/v44.6.0/docs/tutorial/sandbox.md#L15-L20
- `webUtils.getPathForFile(file)` is callable in a preload only (renderer process with context isolation: expose through `contextBridge`); it returns `''` for a File not backed by a disk file and throws for a non-File argument — https://github.com/electron/electron/blob/v44.6.0/docs/api/web-utils.md#L5-L22

## Permission checks and requests (studied for T20, 2026-10-21)

- Two separate hooks: `setPermissionRequestHandler(handler)` answers requests (a page asks, `callback(true|false)`); `setPermissionCheckHandler(handler)` answers synchronous checks (`true` allows). "Most web APIs do a permission check and then make a permission request if the check is denied", and each handler must be implemented for complete handling — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md#L958 and the typings in `node_modules/electron/electron.d.ts` (`setPermissionCheckHandler`, `setPermissionRequestHandler`)
- The check handler receives `(webContents | null, permission, requestingOrigin, details)`; for a cross-origin sub frame `details.embeddingOrigin` is the embedding frame's origin and `requestingOrigin` is the iframe's. The permission names include `storage-access`, `top-level-storage-access`, `persistent-storage`, `notifications`, `media`, `fullscreen`, `unknown` and the sensitive ones used by the app — https://github.com/electron/electron/blob/v44.6.0/docs/api/structures/permission-check-handler-handler-details.md and the `permission` union in `electron.d.ts`
- A check handler that returns `false` for everything but media refuses `storage-access`: sign-in pages that embed a cross-origin frame (accounts.x.ai under grok.com) are refused cookie and storage access and stop. Without a handler, Electron answers `true` for the checks Chromium issues here — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md#L958
- Probe, Electron 44.6.0 on this machine (`.claude/scratch/probe/main.js`, parent page on 127.0.0.1, iframe on localhost, `navigator.permissions.query` inside the iframe): no handlers -> storage-access, notifications, persistent-storage `granted`; geolocation, midi, clipboard-read, camera, microphone `denied` (these are not decided by the check handler: a handler that logs sees only storage-access, notifications and persistent-storage); check handler returning `false` for all -> every one `denied`, including storage-access — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md#L958
- The app's policy follows from this: the check handler refuses only the sensitive set (media, geolocation, notifications, clipboard-read, display-capture, midi, hid, serial, usb, idle-detection) unless it is `media` from the agent's own origin, and answers `true` otherwise, which is the default; the request handler is unchanged — `src/shared/site-policy.ts` — https://github.com/electron/electron/blob/v44.6.0/docs/api/session.md

## Colour scheme in the renderer and in tests (studied for 05-design-contrast T01, 2026-10-23)

- `nativeTheme.themeSource` is `system`, `light` or `dark`, default `system`; `system` "will remove the override and everything will be reset to the OS default". `dark` and `light` make the `prefers-color-scheme` CSS query match that mode and emit `updated`; `nativeTheme.shouldUseDarkColors` reports the effective value — https://github.com/electron/electron/blob/v44.6.0/docs/api/native-theme.md#L28-L52
- Probe, Electron 44.6.0 (Chromium 152.0.7977.130) on macOS with the OS set to Dark, a hidden `BrowserWindow` loading a local page, no Playwright: with `themeSource = 'system'` the page matches `prefers-color-scheme: dark`; setting `light` then `dark` then `system` then `dark` then `light` flipped `matchMedia('(prefers-color-scheme: dark)').matches` and the `@media` CSS (body background `rgb(0, 0, 0)` / `rgb(255, 255, 255)`) each time within 300 ms, and a `change` listener on the media query fired three times (`dark=false`, `dark=true`, `dark=false`; the no-op `system` to `dark` hop with the OS already dark fires nothing). So the renderer follows `nativeTheme` live and an app that never sets `themeSource` follows the OS setting — https://github.com/electron/electron/blob/v44.6.0/docs/api/native-theme.md#L28-L52 and `tasks/10-app-shell/05-design-contrast/spikes/raw-result.txt` (EVIDENCE EL1)
- Under Playwright `_electron.launch` the page does NOT follow `nativeTheme`: Playwright emulates `prefers-color-scheme: light` by default ("Defaults to 'light'"), so with the OS in Dark mode the probe page matched `light` at start and after `themeSource = 'dark'`, and fired no `change` event. Setting `themeSource` through `electronApp.evaluate` therefore cannot force a scheme in the smoke — https://github.com/microsoft/playwright/blob/v1.63.0/docs/src/api/params.md#L733-L738 and `tasks/10-app-shell/05-design-contrast/spikes/result.txt` (EVIDENCE EL2)
- A Playwright test forces a scheme in two ways, both seen working on this version: `page.emulateMedia({ colorScheme: 'light' | 'dark' })` flips the page live in both directions (a `dark` to `light` round trip returned the light palette), and `electron.launch({ colorScheme: 'dark' })` starts the window in that scheme (`'light'` likewise; `null` starts in the OS scheme, here dark; omitted starts light). `emulateMedia({ colorScheme: null })` removes the emulation, after which `nativeTheme.themeSource = 'dark'` reaches the page again. The smoke for the palettes uses `page.emulateMedia` per scheme — https://github.com/microsoft/playwright/blob/v1.63.0/docs/src/electron-api/class-electron.md#L126 and https://github.com/microsoft/playwright/blob/v1.63.0/docs/src/api/params.md#L733-L738 and `tasks/10-app-shell/05-design-contrast/spikes/result.txt` and `tasks/10-app-shell/05-design-contrast/spikes/launch-option-result.txt` (EVIDENCE EL3)
- `window.matchMedia('(prefers-color-scheme: light)')` with a `change` listener is the renderer's live-switch hook (xterm needs a new `options.theme` object on each change, see `docs/tech/xterm@6.0.0.md`) — https://developer.mozilla.org/en-US/docs/Web/API/MediaQueryList/change_event
