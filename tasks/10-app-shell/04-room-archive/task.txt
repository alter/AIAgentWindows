TASK: room archive — saved rooms the owner can reopen and continue

GOAL
  A room survives the application: every room is a record on disk next to its
  markdown history, the Room pane lists the saved rooms, an opened room shows
  its feed, participants and settings, allows "Carry result" and a new run in
  the same room with the whole earlier history in the participants' context.
  Owner's request of 2026-10-22: closing the app currently loses the room
  (docs/PROJECT.md §3, Room row). Serves no gate.

CONTEXT
  tasks/10-app-shell/02-room/task.txt

SCOPE
  + S1 room record: <shared>/rooms/<id>.json with config (participants, mode, rounds, finalizer, timeout), entries, status, created and updated times; written atomically after every entry and status change; the markdown history stays as it is for participants and people
  + S2 room list in the Room pane: saved rooms newest first with id, time, status and the first line of the first prompt; opening one rebuilds the RoomSnapshot from the record (feed, chips, participants, settings prefilled) and enables "Carry result"
  + S3 continue a room: a new prompt in an opened room starts a run with the same room id, appends to the same record and history file, and the participants receive the whole earlier history through the existing prompt builder; participant sessions are fresh (a CLI session is not kept across app starts)
  + S4 interrupted run: a record found with status running at app start is saved as stopped before anything else; nothing is relaunched by the app
  + S5 on app start the Room pane opens the most recent room; a Room with no records opens empty as today
  + S6 a record that fails to parse is listed as unreadable and skipped, never deletes or rewrites the file
  − deleting or renaming rooms — later, on request
  − resuming the CLI sessions of a continued room (claude --resume, codex exec resume) — not needed while the prompt carries the whole history; a later task if the context grows too large
  − relaunching the remaining turns of an interrupted run — owner's decision 2026-10-22: save as stopped, continue by hand
  indivisible: the record is written by the run, read by the service and rendered by the pane in one shape
