TASK: room participants — several sessions of one CLI with their own model and effort

GOAL
  A Room participant is an instance, not an agent kind: the owner adds three
  Claude Code participants (Fable 5.1; Opus 5.5 effort high; Sonnet 5.5 effort
  medium) or several Codex ones, and the relay passes the room history between
  them exactly as it does today between CLI and site participants. Owner's
  request of 2026-10-22 (docs/PROJECT.md §3, Room row). Serves no gate.

SCOPE
  + S1 evidence first (ARCH): how each pinned CLI names its models and effort levels — the model flag, the alias rule ("opus" = the latest supported Opus), the effort flag or config key, and whether the CLI can enumerate its supported models (a command, a cache file, or nothing); recorded in docs/tech/claude-code@2.1.306.md and docs/tech/codex@0.163.0.md with URLs before any code
  + S2 participant model: a participant is {id, kind, label, model?, effort?}; several participants of one CLI kind are allowed; site participants stay one per site; validation bounds model and effort to the CLI's own vocabulary (alias or full name, effort levels of that CLI)
  + S3 models are never listed by the app: the model names the owner types are passed to the CLI as its own aliases or full names, so "opus" follows the CLI to the latest Opus; when the pinned CLI exposes an enumeration (S1) the UI offers it as suggestions, otherwise the field is free text
  + S4 turn spawn: buildRoomTurnSpawn passes model and effort with the flags found in S1; absent values pass nothing, so the CLI keeps its own default
  + S5 Room UI: an "add participant" row (kind, model, effort) and removal; the participant list persists in the Room state between app starts; feed labels and progress chips distinguish instances ("Claude · opus · high")
  + S6 history and carry: author labels in <shared>/rooms/<id>.md and in "Carry result" use the instance label
  − per-participant model or effort for site participants — not offered by the sites' free accounts; no task
  − changing the model or effort of the owner's working windows — the owner's own CLI settings
  − OpenAI API participants — the OpenAI API provider task
  indivisible: the participant record is read by the model, the spawn builder, the drivers and the UI in one invariant
