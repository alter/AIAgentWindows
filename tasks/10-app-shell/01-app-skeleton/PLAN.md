# Application skeleton — one Slack-like window with CLI and web agents

## Goal
`npm run build && npx electron .` opens one window: a sidebar lists agents, "+" adds a Claude Code or Codex agent (folder picked in a dialog, CLI in an xterm pane over node-pty) or a ChatGPT, Grok or DeepSeek agent (embedded `WebContentsView`, own `persist:` partition, Back/Forward/Home/Reload); clicking an agent shows it; after a restart every agent is back (CLI sessions resumed, sites still signed in). The fast and full tiers of `docs/PROJECT.md` §6 run green, and an architecture check keeps Node and main-process code out of the renderer.

## Assumptions
- Build: esbuild bundles three entry points — `src/main/index.ts` (cjs, platform node, external `electron`, `node-pty`), `src/preload/index.ts` (cjs, external `electron`), `src/renderer/index.ts` (iife, browser) — into `dist/`; `src/renderer/index.html` and CSS are copied. One root `tsconfig.json` (`noEmit`, strict, DOM + node types) so `npx tsc --noEmit` checks everything; the architecture check, not tsconfig, keeps the layers apart.
- Layout: `src/shared/` (pure types and functions: agent kinds, state schema, CLI argv builder, site policy, codex claim) — unit-tested and the coverage target; `src/main/` (Electron glue: window, IPC, pty manager, views, state file); `src/preload/` (the app renderer's contextBridge only); `src/renderer/` (DOM UI, xterm). Coverage counts `src/shared/**` and `src/main/pty-manager.ts`, `src/main/state-file.ts`; Electron glue and renderer DOM are left to the Playwright smoke, recorded in PROJECT.md §6 "Areas deliberately left uncovered".
- CLI spawn: macOS/Linux `[$SHELL || /bin/zsh, '-l', '-i', '-c', 'exec "$@"', 'agent-shell', <cli>, ...args]` with `cwd` as a spawn option; Windows spawns the CLI directly (unverified here, per-OS task). The CLI path is overridable by `AIAW_CLAUDE_BIN` / `AIAW_CODEX_BIN` for tests (the stub).
- Shared directory: `<userData>/shared` created at start; only passed as `--add-dir` in this plan.
- State file: `<userData>/agents.json`, `{ version: 1, agents: [{ id, kind, title, cwd?, sessionId?, createdAt }] }`; written atomically (tmp + rename).
- Site agents: one `WebContentsView` per agent attached to the main window's `contentView`, bounds = content area minus a 36 px navigation bar drawn by the renderer; only the selected view is visible. `setWindowOpenHandler` opens popups in a child window with the same partition, no preload.
- Tests set `AIAW_USER_DATA` to a temporary directory; the app reads it before `ready` and calls `app.setPath('userData', …)`.
- If a worker finds a pinned API that behaves unlike its `docs/tech/` note, it stops and reports (`open:` line); the main session runs `/diagnose`.
- `vitest.config.ts` (T02) adds no new check: it configures the vitest commands already declared in docs/PROJECT.md §6 (the coverage command of `.coverage-gate.json` in the fast tier, `npx vitest run tests/full` in the full tier). Same for `eslint.config.mjs` (`npx eslint .`) and `playwright.config.ts` (`electron-smoke`, T14).
- T02: npm 10.9.4 fails `npm install` with `Cannot read properties of null (reading 'edgesOut')` (arborist `#loadPeerSet`) on vitest 5.0.3's peer set, reproduced with vitest alone on both registry.npmmirror.com and registry.npmjs.org and absent with `--legacy-peer-deps`; `.npmrc` with `legacy-peer-deps=true` is committed (added to WRITE-SET). Peers are then not auto-installed, so required peer `vite` 8.3.3 (vitest peer `^6.4 || ^7 || ^8`, published 2026-10-06) and `@types/node` 22.20.5 (matches Node 22, published 2026-10-01) are explicit devDependencies.
- T02: `eslint.config.mjs` also ignores `tasks/` (the 05-feasibility spike scripts are CommonJS evidence artefacts, 24 errors under the recommended rules); `src/shared/app-info.ts` + `tests/unit/app-info.test.ts` is the placeholder pair that gives the coverage ratchet a real file until T03 (floor set to 100.00 on it).
- T02 integrity: `vitest.config.ts` is new and is the config of the coverage command already declared in docs/PROJECT.md §6 (Coverage table); no suppression, no skipped test.

- T05: `tests/fixtures/stub-cli.mjs` starts with a `#!/usr/bin/env node` line (it is exec'd through `AIAW_CLAUDE_BIN` by `buildSpawn`), so the `// stub-cli.mjs` filename comment is line 2; the env test goes through `buildSpawn` with `platform: 'win32'` (direct spawn, no login shell) so the host's zsh rc files cannot alter the output.
- T06: `claimRollout({spawnedAtMs, cwd, claimed, rollouts})` takes `Rollout = {fileName, firstLine, createdAtMs}` (the caller lists `$CODEX_HOME/sessions/YYYY/MM/DD`, reads the first line and the file birth time) and returns the earliest-created unclaimed rollout with `createdAtMs >= spawnedAtMs` whose first line is `session_meta` with `payload.cwd` equal to the window's cwd (and `payload.id`, when present, equal to the file-name uuid); only the first-line form is covered, the paginated form (CX15) is left to the last-reply task.
- T03: `parseState(text)` takes the file text and returns an empty state when any part is invalid (bad JSON, version, size over 1 MB, any malformed or duplicate-id agent, non-UUID `sessionId`, `cwd`/`sessionId` on a site agent); partial salvage is not attempted. The malformed-UUID test string is built from a valid id with `slice` because gitleaks flags a literal fake UUID as `generic-api-key`.

- Codex creates its rollout file only when the session is first persisted, not at spawn (recorder.rs at rust-v0.159.2: "For newly created sessions, this precomputes path/metadata and defers file creation/open until an explicit persist() call"). T13 therefore claims lazily: on app quit, when the agent list is saved, and before restore; an unclaimed Codex agent restores as a fresh `codex` in its folder (coordinator note, 2026-10-21).

- arch_check (T09) sees `preload` only in constructor arguments written inline; T12 writes the `WebContentsView` and popup-window options for sites inline, never through a shared options variable (coordinator note, 2026-10-21).

- T10 spawns the CLI when the agent is added, before the renderer has a pane. T11 must not lose that early output: main keeps a per-agent ring buffer of pty output (cap 256 KB) and the renderer, on creating a pane, asks for the backlog and then follows `pty:data`; the pane reports its size so main calls `pty.resize` (FitAddon never resizes the pty) (coordinator note, 2026-10-21).

- Site views have no automated coverage after T12 (only a deleted scratch probe). T14's smoke also adds a DeepSeek agent whose start URL is replaced, in tests only, by a local page served from `tests/fixtures/` (`AIAW_SITE_URL_<KIND>` override read by main; never set in production) and asserts: the view is visible, its user agent has no `Electron/`, Home returns to the start URL after navigating away. Tests never load the real sites (docs/PROJECT.md §5) (coordinator note, 2026-10-21).

- T13: restore lives in `src/shared/restore.ts` (`restoreSpawn`, `claimForAgents`) and `AgentController.restore()/flush()`; a Codex agent without a session id is first matched against rollouts created after its `createdAt` (before restore), and if none, restored as a fresh `codex` whose lower bound becomes the new spawn time; claims run in `persist()` (every add) and on quit (`before-quit` is deferred once until `flush()` finished). An agent whose folder is gone or whose spawn throws stays listed with an empty pane. A Claude session that never received a message may fail `claude --resume` (CLI behaviour, not handled here). `src/main/codex-rollouts.ts` lists `$CODEX_HOME||~/.codex/sessions/YYYY/MM/DD` for days from the lower bound -1 day to +1 day (max 60 days).
- T14: `siteStartUrl(kind, env)` in src/shared/site-policy.ts reads `AIAW_SITE_URL_<KIND>` (http/https only, else the production URL); `SiteViews` takes `env` as a third constructor argument (main passes `process.env`). `vitest.config.ts` gets `passWithNoTests: true` because the §6 command `npx vitest run tests/full` exits 1 on an empty directory (no test is skipped or removed). `playwright.config.ts` has a globalSetup (`tests/full/global-setup.ts`) that runs `scripts/build.mjs`, so the night run never tests a stale `dist/`; the smoke sets `AIAW_CODEX_BIN` to the stub as well so no test can spawn a real CLI. `test-results/` added to .gitignore. Fixed a T05 stub race (see NOTES.md).
