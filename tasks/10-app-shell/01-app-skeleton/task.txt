TASK: application skeleton

GOAL
  A runnable Electron 44.6.0 app: one Slack-like window whose sidebar lists
  agents (Claude Code, Codex, ChatGPT, Grok, DeepSeek); CLI agents run in a
  terminal pane, web agents in an embedded view with navigation; the agent list
  survives a restart; the fast and full gate tiers of docs/PROJECT.md §6 run green.

SCOPE
  + S1 npm project with exact pinned versions, build (esbuild), tsc, eslint, vitest with coverage ratchet, Playwright Electron smoke; every electron-builder command carries --publish never; no npm script named release; postinstall sets the execute bit of node-pty's spawn-helper
  + S2 main window: sidebar of agents, "+" to add an agent of each kind, selection switches the content area
  + S3 CLI agents (Claude Code, Codex): folder picked at creation; spawned through the login shell with argv passed by exec "$@" (no string interpolation); claude gets a fresh --session-id and --add-dir <shared dir>; CLAUDE_CODE_CHILD_SESSION removed from the child environment; xterm.js pane; Ctrl+V/Alt+V go to the pty untouched; a dropped file is pasted as its quoted path
  + S4 web agents: WebContentsView per agent with its own persist: partition, no preload; Back/Forward/Home/Reload; DeepSeek user agent without the Electron token (D1); permissions: media and persistent-storage for the agent's own origin, everything else refused
  + S5 persistence: the agent list is stored in userData and restored at start (claude --resume <id>, codex resume <claimed id>, sites reload their partition)
  + S6 a stub CLI used by every pty test; tests never spawn the real claude or codex, never open the owner's userData
  + S7 architecture check in the gate: the renderer imports no Node or main-process module, remote views get no preload
  − Forward, shared directory content, last-reply adapters — next tasks of 10-app-shell
  − Import of existing local sessions with filters — its own task of 10-app-shell
  − OpenAI API provider — later
  − Windows and Ubuntu verification — per-OS tasks closed by the owner
  − Release builds, signing, publishing — absent in the ledger
  indivisible: the window, the IPC contract and the panes share one state model; workers run it as sequential plan tasks, not as parallel parts
