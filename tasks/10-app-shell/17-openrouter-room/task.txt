TASK: openrouter room — OpenRouter models take part in a Room like the CLIs and sites

GOAL
  An "OpenRouter" row in the participants table picks any OpenRouter model
  (Free / Paid filter), an effort when the model supports one, and web search
  on or off; several OpenRouter rows can share a room; each turn gets the whole
  room history like every other participant. Owner's request and answer of
  2026-10-23 (docs/PROJECT.md §3, OpenRouter row).

CONTEXT
  docs/tech/openrouter@2026-10-23.md (S3 models, S4 completions and reasoning, S5 web search, errors, Implications: Room turns)
  src/main/room-drivers.ts (CliDriver, SiteDriver: one turn per call)
  src/shared/room-model.ts (RoomParticipant, kinds, parse), src/shared/room-history.ts (buildParticipantPrompt)
  src/renderer/room-table.ts, src/shared/room-view.ts (Add participant menu, rows)
  tasks/10-app-shell/16-openrouter-account/PLAN.md

SCOPE
  + S1 participant kind `openrouter` with `model` (an OpenRouter id), optional `effort` (only a value in the model's supported_efforts) and `web` (boolean); parse and validation in room-model; old records load
  + S2 table row: Model is a searchable select of the cached model list with a Free / Paid / All filter (price shown), Effort shows the model's supported efforts or "—", a Web checkbox (on by default for paid models, off for :free, with the per-search price noted); "OpenRouter" in Add participant is disabled with its reason when signed out
  + S3 driver: one non-streaming POST /api/v1/chat/completions per turn with the participant prompt built like for the CLIs, reasoning effort when set, the web_search server tool when on, attribution headers; the reply is choices[0].message.content; abort on Stop and on the turn timeout
  + S4 errors as failed turns with a readable text: 401 (signed out), 402 (no credits), 429 (Retry-After honoured once), 200 with error or finish_reason error, empty content with finish_reason length ("raise the limit")
  + S5 labels "OpenRouter · <model name>" (+ effort), unique ids per row
  − the chat agent — 10-app-shell/18-openrouter-chat
  − streaming in the room — not needed, one reply per turn
  indivisible: the participant kind, its row and its driver form one contract tested by one integration run
