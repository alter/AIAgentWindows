TASK: room resume — a stopped run continues from its first unanswered turn

GOAL
  After Stop (or an app quit mid-run) the owner presses the start button with
  the same prompt and the same setup and the run goes on from the first turn
  that has no answer; answered turns are not asked again. Owner's request of
  2026-10-23 ("нажал stop и затем continue - почему все с нуля началось? у нас
  же промпт тот же, ответы от моделей уже имеются"). Serves no gate.

SCOPE
  + S1 resume point (pure, src/shared): from a room record, the last run segment (entries after the last owner prompt) is resumable when the record status is stopped or failed and the segment has no final entry; done turns are the (authorId, round) pairs of the segment's reply and error entries without state stopped; the result names the segment prompt and the done turns
  + S2 room:start takes an optional `resume: true` with continueId; the main process computes the resume point from the stored record and refuses when there is none or when the requested prompt, mode, rounds, participants or finalizer differ from the record's (turn timeout and site debug may change); the renderer is never trusted for which turns are done
  + S3 a resumed run appends no new owner prompt, skips the done turns (relay: in schedule order; broadcast: the missing participants of the interrupted round with the entries seen at that round's start, then the remaining rounds), then the finalizer; progress counts start at the done turns; the turn cut by Stop is asked again; CLI sessions start fresh and get the earlier entries as on continue today
  + S4 the button reads Resume when the opened room is resumable and the prompt box and setup equal the stopped run's; editing the prompt or the setup turns it back to Continue (a new prompt, as today); refused resume shows its error
  + S5 on resume the Room "stopped" entries of the resumed segment are dropped: the record and the markdown history are rewritten atomically without them, the feed no longer shows them and participants never receive them; after Continue with a new prompt the stop entry of the old segment stays (that run really ended stopped)
  − a new prompt in the same room (Continue) — unchanged, 10-app-shell/04-room-archive
  − resuming after the setup was changed (participants added or removed) — the button falls back to Continue
  − partial text of the turn cut by Stop — discarded as today
  indivisible: the resume point, the run loop and the button rule share one contract and the same smoke specs
