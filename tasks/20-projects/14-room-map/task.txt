TASK: project map for web and OpenRouter participants, the budget, the digest and its disclosure

GOAL
  A project room sends its web and OpenRouter participants the project map next to the
  history: once per run, one attachment for a web page (the same text inlined when the page
  cannot take files), a system part cut to the model's context for OpenRouter with
  `provider.data_collection: "deny"` and `max_completion_tokens` only when the model
  reports one. Every turn records a digest of what was sent, which survives a rename, a
  restart and a continuation and shows in the feed as "Context sent"; the room says which
  sites and models receive the map (docs/plans/projects.md D11, D12, D13, D22, D25, T17).
  Serves milestone M3: project rooms usable with every participant kind.

SCOPE
  + shared/context-digest.ts: the digest of a turn and its parser; `parseEntry` keeps it, so a rename, a reopen and a continuation do not lose it
  + shared/pack-fit.ts: history takes precedence, the map shrinks first, the oldest entries go next, the latest prompt stays
  + shared/context-sent.ts: the "Context sent" view of a digest and the recipients line (reducers, no DOM)
  + shared/kinds/capabilities.ts: the completion ceiling a model reports, the answer reserve and the input budget at 3 characters per token, `modelCatalog`
  + shared/openrouter.ts: `top_provider.max_completion_tokens` parsed; shared/room-history.ts: the web prompt names the attachment when a map travels with it
  + main/runs/project-map-provider.ts, project-pack.ts, digest.ts: the project-map `ContextProvider`, the pack per recipient kind with its inline fallback and OpenRouter fields, the digest with hashes
  + main/room.ts, room-context.ts, room-service.ts, index.ts: the map built once per run, packs built per recipient, the digest on the turn's entry, the run context carries the catalog and the map collector
  + main/room-drivers.ts, main/openrouter/chat.ts: try-then-inline on `attach-unsupported`; `provider.data_collection` and `max_completion_tokens` in `chatBody` only; a refusal for lack of endpoints is a readable error naming `data_collection`
  + renderer: "Context sent" disclosure under each turn (textContent only), the recipients line above Start
  + tests: unit for each pure module, integration `room-map` on the fake OpenRouter server (4000-context model, ceiling model, "no endpoints" refusal), JSDOM page with and without a file input, stub CLI, secret canaries on every outgoing byte; smoke `projects-map`
  − roles, the orchestrator, pack content stored by hash, any change to a "No project" room's request bytes, to a CLI participant's prompt or to the shared `requestBody` of the streaming chat agent
  − the CLI intro sentence "You may search the web" in a project room (named in the plan notes, left as it is)
