## Decisions made alone
- Where the map lives. Built once per run in `Room.execute` (before the first turn, also on a continuation) through `RoomRunContext.collectMap(limits)`; `RoomService` fills it from the project's folder and the `GitRunner` (`collectProjectMap`); only a room with a site or OpenRouter participant builds one; a failure to build it leaves the run going without a map (the digest then has no `map`). The map text is hashed once (`runMap`, sha256, 16 hex digits) and each turn's digest carries that hash.
- Map limits from the budget (T16 note): `mapLimitsFor` takes a quarter of the smallest OpenRouter input budget as `maxBytes` (at least 1 KiB, at most the default 48 KiB) and a quarter of that for one document; without a known OpenRouter context the defaults stay. A web participant's attachment carries the map as built; only the inline fallback cuts it.
- Budget. `tokenBudget` is the model's `context_length`; characters = tokens x 3; the answer reserve is `min(16384, context / 4)` or the model's reported `top_provider.max_completion_tokens` when that is lower; `max_completion_tokens` is sent only when the model reports one and carries that reserve (never more than the room the request leaves). The system part (intro, map preamble) is counted before the history and the map are fitted. History takes precedence: the map is shrunk to what is left but not below a quarter of the budget (or 200 characters, below which it is dropped), then the oldest history entries go, the owner's latest prompt always stays, and last the map gives up the rest. A single prompt larger than the budget is sent whole (nothing can be cut from it) and the provider answers with its own error.
- Web attachment is always one file: history then map (D22 priority order), merged by the project pack (`composePack` keeps several files for other callers); the prompt says "the project map and the history are in the attached file" (`buildParticipantPrompt` option `projectMap`, other callers unchanged). The fallback text is the intro, the map section and the history rendered fresh, cut to `WEB_INLINE_LIMIT` by the same fit.
- Try-then-inline lives in `SiteDriver`: only a `SiteAdapterError` with code `attach-unsupported` falls back, and only when the request carries `inline` (a project room's web turn with a map). `TurnRequest` gained `inline`, `onInline`, `denyDataCollection` and `maxCompletionTokens`; a "No project" room never sets them.
- Digest shape (`shared/context-digest.ts`): `history { first, last, count }` (indices into the room's entries, `count` is what was sent), `parts[] { id, bytes, hash }` per provider (`history`, `project-map`), `files[] { name, bytes }`, `map` (hash of the run's map, present when a map part was sent), `cut { via: 'budget' | 'inline', entries, mapChars }`. A malformed digest on a stored entry is dropped and the entry kept. Every non-prompt turn that composed a pack carries one, in every room (a plain room too: only its request bytes are unchanged).
- Entry ids do not exist in the model, so "range of history entry ids" is the index range of the entries sent.
- `ModelItem.maxCompletionTokens` is optional and absent when the model reports none, so no existing test object changed. `NO_CATALOG` stays the catalog of a plain room; the project room's catalog is `modelCatalog(models)` built from the list the room start already fetched for `openrouterProblem`.
- The "no endpoints" text is made only when the request denied collection and the answer is 404 with "no endpoints" in its message; any other failure keeps its text.
- The fake server's new models are `fakeModelsWithLimits()` (`acme/small-context` 4000, `acme/ceiling` reporting 2048, `acme/no-endpoints:free`), not added to `fakeModels()` so no count in an existing spec moved; the refusal answers 404 only when the body carries `provider.data_collection: "deny"`.
- Coverage include: `src/shared/**` and `src/main/runs/**` already hold every new module (no change to `vitest.config.ts`); the renderer modules are outside it and covered by the smoke spec.
- `.env`, key and token canaries: the project fixture has `.env`, `.npmrc` with a token, `key.pem`, `id_rsa`, `config/credentials.json`, and a `README.md` that is a symlink to a file outside the project; the map lists none of them and reads no content from them (the walk fallback is used, `git ls-files` through the same filters is T16's test).
